# 1. Нотация: как читать формулы семинара

Семинар сразу вываливает `$\mathbf{y} = X\mathbf{w}$`, `$\ell$`, `$\langle \cdot, \cdot \rangle$` и не объясняет ни одного значка. Разберём их, иначе дальше читать бесполезно.

## Буквы

| значок | что это | в нашем случае |
|---|---|---|
| `ℓ` | **количество объектов** (строк в таблице) | 50 точек |
| `n` | **количество признаков** (колонок) | 1 признак |
| `X` | матрица признаков, размер `ℓ × n` | 50 × 1 |
| `y` | столбец правильных ответов, длина `ℓ` | 50 чисел |
| `w` | вектор весов, длина `n` | пока одно число |
| `b` | свободный член (bias, смещение) | одно число |

`ℓ` — это греческая «эль», читается «эль». Авторы используют её вместо `n`, потому что `n` у них занято под число признаков.

**Жирный шрифт** (`**w**`, `**y**`) означает **вектор**, а не одно число. Обычный шрифт — скаляр. В коде это разница между `5` и `np.array([5, 3, 1])`.

## Формула из главы 1 семинара

```
y = w₁x₁ + w₂x₂ + ... + wₙxₙ + b
```

Это ровно то, что ты знаешь как `y = wx + b`, только признаков несколько. Каждый признак `xᵢ` умножается на свой вес `wᵢ`, всё складывается, плюс `b`.

Пример с тремя признаками:

```
цена квартиры = 100·площадь + 50·этаж − 20·удалённость + 1000
                 ↑w₁           ↑w₂        ↑w₃              ↑b
```

## Скалярное произведение ⟨w, x⟩

Семинар пишет:

```
y = ⟨w, x⟩
```

Угловые скобки — это **скалярное произведение**. Означает: перемножь поэлементно и сложи.

```
w = (2, 3, 5)
x = (10, 1, 4)

⟨w, x⟩ = 2·10 + 3·1 + 5·4 = 20 + 3 + 20 = 43
```

То есть это просто короткая запись суммы `w₁x₁ + w₂x₂ + ... + wₙxₙ`.

В numpy это `w @ x` или `np.dot(w, x)`.

## Куда делся b

Самый сбивающий момент. Семинар пишет:

> Часто предполагают, что объект `x` содержит в себе фиктивный признак равный 1

Идея такая: вместо того чтобы таскать `b` отдельно, **добавляем к каждому объекту ещё один признак, всегда равный единице**, и приписываем ему вес `b`.

```
было:  y = w₁x₁ + w₂x₂ + b

стало: x = (x₁, x₂, 1)        ← добавили единицу
       w = (w₁, w₂, b)        ← добавили b как обычный вес

       ⟨w, x⟩ = w₁x₁ + w₂x₂ + b·1 = w₁x₁ + w₂x₂ + b
```

Результат тот же, но теперь в формуле нет отдельного слагаемого — всё спряталось в скалярное произведение. Это сильно упрощает матричные выкладки дальше.

В коде семинара это строка:

```python
X_train = np.hstack((X, np.ones((l, 1))))
```

`np.ones((l, 1))` создаёт столбец из `l` единиц, `hstack` приклеивает его справа к `X`.

Проверил на 8 точках:

```
X до:          (8,)     одномерный массив
X[:, newaxis]: (8, 1)   столбец
после hstack:  (8, 2)   добавился столбец единиц

первые три строки:
   [[-5.00  1.00]
    [-3.57  1.00]
    [-2.14  1.00]]
```

Теперь `X_train @ w`, где `w = [w₁, b]`, даёт `x·w₁ + 1·b` — ту же прямую.

## Матричная запись y = Xw

Если собрать все объекты в матрицу, то все предсказания считаются **одним умножением**:

```
      X          @     w     =   y_pred
   (ℓ × n)         (n × 1)      (ℓ × 1)

  ┌         ┐      ┌   ┐       ┌      ┐
  │ x₁₁ x₁₂ │      │ w₁│       │ ŷ₁   │
  │ x₂₁ x₂₂ │   @  │ w₂│   =   │ ŷ₂   │
  │ x₃₁ x₃₂ │      └   ┘       │ ŷ₃   │
  └         ┘                  └      ┘
```

Каждая строка матрицы — один объект. Умножение строки на вектор весов даёт предсказание для этого объекта.

Правило размерностей: `(ℓ × n) @ (n × 1) = (ℓ × 1)`. Внутренние размеры должны совпасть — иначе numpy ругнётся.

## Функция потерь из семинара

```
L(w) = (1/ℓ) ‖y_pred − y‖²
```

Двойные палочки `‖·‖` — это **норма вектора**, а `‖·‖²` — сумма квадратов его компонент:

```
‖(3, 4)‖² = 3² + 4² = 25
```

Значит:

```
‖y_pred − y‖² = (ŷ₁−y₁)² + (ŷ₂−y₂)² + ... + (ŷ_ℓ−y_ℓ)²
```

А с делением на `ℓ`:

```
L(w) = (1/ℓ) Σ (ŷᵢ − yᵢ)²
```

**Это та же самая MSE**, которую ты считал на четырёх точках в [ml_math](../../ml_math/02_oshibka.md). Просто записана через норму вместо суммы — компактнее, но означает ровно то же.

Индекс `2` внизу у `‖·‖₂` означает «евклидова норма» — обычная, через квадраты. Бывают другие, но в MSE всегда эта.
