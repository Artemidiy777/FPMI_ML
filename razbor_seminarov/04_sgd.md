# 4. Стохастический градиентный спуск

## Проблема, которую он решает

Обычный градиентный спуск на каждом шаге проходит по **всей выборке**:

```
grad = (2/ℓ) · Xᵀ(y_pred − y)
                ↑
         здесь участвуют ВСЕ ℓ объектов
```

На 50 точках это мгновенно. На миллионе объектов и тысяче признаков — каждый шаг становится дорогим, а шагов нужны тысячи.

Семинар формулирует так: «считать градиент по всей обучающей выборке на каждом шаге слишком дорого».

## Идея

Считать градиент не по всем объектам, а по **случайному подмножеству** фиксированного размера. Такое подмножество называется **батч** (batch, пачка).

Логика: градиент по 10 случайным объектам — **приблизительная оценка** настоящего градиента. Направление будет неточным, зато посчитается в сотни раз быстрее. А неточность компенсируется количеством шагов: лучше сделать тысячу грубых шагов, чем десять идеальных.

Слово «стохастический» и означает «случайный».

## Два способа реализации

Семинар описывает оба.

**Способ 1 — случайный батч каждый раз.** На каждом шаге independently выбираем `k` случайных объектов. Просто, но некоторые объекты могут не попасться ни разу, а некоторые по многу раз.

**Способ 2 — эпохи.** Перемешиваем всю выборку, режем на батчи подряд, проходим все. Это одна **эпоха**. Потом перемешиваем заново и повторяем. Каждый объект участвует ровно один раз за эпоху.

Способ 2 используется на практике почти везде. Его и просят написать в домашке — через генератор с `yield`.

В семинаре реализован **способ 1**, как более простой.

## Разбор класса

```python
class MySGDLinearRegression(MyGradientLinearRegression):
    def __init__(self, n_sample=10, **kwargs):
        super().__init__(**kwargs)
        self.w = None
        self.n_sample = n_sample
```

Наследуется от градиентной версии. Добавлен один параметр — `n_sample`, размер батча, по умолчанию 10.

Обрати внимание на изящество: **переопределён только один метод**, `_calc_gradient`. Весь цикл обучения, `predict`, `get_weights` достались по наследству. Именно ради этого градиент и выносили в отдельный метод в прошлой главе.

```python
    def _calc_gradient(self, X, y, y_pred):
        inds = np.random.choice(np.arange(X.shape[0]), size=self.n_sample, replace=False)
        grad = 2 / self.n_sample * X[inds].T @ (y_pred[inds] - y[inds])
        return grad
```

**Строка 1 — выбрать объекты:**

```python
np.arange(X.shape[0])     # [0, 1, 2, ..., ℓ−1]  все номера строк
np.random.choice(..., size=10, replace=False)
```

- `size=10` — выбрать 10 номеров
- `replace=False` — **без повторов**, один объект не попадёт в батч дважды

Получается, например, `inds = [17, 3, 42, 8, ...]`.

**Строка 2 — посчитать градиент только по ним:**

```python
X[inds]        строки матрицы с этими номерами
y[inds]        соответствующие ответы
y_pred[inds]   соответствующие предсказания
```

`X[inds]` — это **индексация массивом**, удобная штука numpy: передаёшь список номеров и получаешь только нужные строки.

Дальше формула та же, что в обычном спуске, только:

```
2 / self.n_sample      вместо   2 / ℓ          делим на размер батча, а не выборки
X[inds]                вместо   X              только выбранные строки
```

## Чем отличаются результаты

Главное наблюдение: **график потерь у SGD шумный**.

```
обычный спуск:          SGD:
   ╲                       ╲
    ╲                       ╲╱╲
     ╲___                    ╲ ╱╲__
         ───                  ╲╱   ╲╱──
```

Обычный спуск всегда идёт точно вниз — градиент посчитан по всем данным. SGD иногда делает шаг «вбок» или даже вверх, потому что случайные 10 объектов могут дать обманчивое направление.

При этом **в среднем** он движется туда же и приходит примерно в ту же точку.

## Неочевидная польза шума

Для линейной регрессии шум — просто издержка. Но в сложных задачах, где у функции потерь много локальных минимумов, случайность **помогает**: шумный шаг может выбить модель из плохой ямы.

Поэтому SGD и его потомки (`Adam`, `RMSProp`) используются при обучении нейросетей, а точные методы — нет.

## Три термина, которые путают

| термин | что значит |
|---|---|
| **батч** (batch) | пачка объектов, по которой считается один градиент |
| **итерация** | один шаг спуска, то есть одно обновление весов |
| **эпоха** | полный проход по всей выборке |

Если в выборке 1000 объектов и батч 100, то одна эпоха = 10 итераций.

## Разновидности по размеру батча

| размер батча | название | характер |
|---|---|---|
| вся выборка | Batch GD (обычный) | точный, медленный |
| 1 объект | «чистый» SGD | очень шумный |
| 32–256 | Mini-batch SGD | стандарт на практике |

Семинарский класс с `n_sample=10` — это mini-batch вариант.

Терминологическая путаница: словом «SGD» сегодня почти всегда называют mini-batch версию, хотя исторически оно означало батч из одного объекта.
