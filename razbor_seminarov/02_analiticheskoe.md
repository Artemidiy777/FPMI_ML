# 2. Аналитическое решение и класс MyLinearRegression

## Что значит «аналитическое»

Решить задачу **аналитически** — значит получить ответ по формуле, за один раз, без итераций. Противоположность — **численно**, когда ответ ищут приближённо, шагами (как градиентный спуск).

Для линейной регрессии аналитическое решение существует:

```
w = (XᵀX)⁻¹ Xᵀ y
```

Эту формулу называют **нормальным уравнением**. Семинар даёт её с неба — разберёмся, откуда она.

## Откуда она берётся

Помнишь из [ml_math, глава 4](../../ml_math/04_chastnye.md), как мы искали минимум? Приравняли все частные производные к нулю и решили систему. Здесь ровно то же, только в матричной записи.

**Шаг 1.** Раскрываем функцию потерь:

```
L(w) = (1/ℓ) ‖Xw − y‖²
     = (1/ℓ) (Xw − y)ᵀ(Xw − y)
```

Запись `aᵀa` — это и есть сумма квадратов компонент вектора `a`, то есть `‖a‖²`. Транспонированный вектор, умноженный на себя, даёт одно число.

**Шаг 2.** Раскрываем скобки:

```
L(w) = (1/ℓ) (wᵀXᵀXw − 2yᵀXw + yᵀy)
```

Это та же операция, что `(a − b)² = a² − 2ab + b²`, только для матриц.

**Шаг 3.** Берём градиент по `w` и приравниваем к нулю:

```
∂L/∂w = (2/ℓ)(XᵀXw − Xᵀy) = 0
```

**Шаг 4.** Решаем:

```
XᵀXw = Xᵀy                   ← перенесли
w = (XᵀX)⁻¹ Xᵀy              ← умножили слева на обратную матрицу
```

`(XᵀX)⁻¹` — **обратная матрица**. Для матриц нет деления, вместо него умножают на обратную. Аналог: вместо `x = 6/3` пишут `x = 3⁻¹·6`.

## Проверка на числах

Я посчитал обоими способами на восьми точках:

```
w = (XᵀX)⁻¹Xᵀy  ->  [4.7183, 7.7682]     (наклон, свободный член)
sklearn         ->  [4.7183, 7.7682]
```

Совпало. `LinearRegression` внутри делает именно это.

## Разбор класса построчно

```python
class MyLinearRegression:
    def __init__(self):
        self.w = None
```

Конструктор. При создании объекта весов ещё нет — они появятся после `fit`. `None` означает «пока пусто».

```python
    def fit(self, X, y):
        X = np.array(X)
        y = np.array(y)
```

`fit` — обучение. Первым делом приводим вход к numpy-массиву: вдруг передали список или `DataFrame`.

```python
        assert len(y.shape) == 1 and len(X.shape) == 2
        assert X.shape[0] == y.shape[0]
```

**Проверки.** `assert` — это «убедись, что условие верно, иначе упади с ошибкой». Здесь проверяется:

- `y` одномерный (столбец ответов, а не матрица)
- `X` двумерный (таблица)
- число строк совпадает: сколько объектов, столько и ответов

Это защита от типичных ошибок. Без них ошибка вылезла бы позже и в непонятном виде.

```python
        y = y[:, np.newaxis]   # ℓ, 1
```

**Критическая строка**, и семинар её не объясняет. `np.newaxis` превращает одномерный массив в столбец:

```
было:  y.shape = (50,)     одномерный
стало: y.shape = (50, 1)   столбец
```

Зачем это нужно — объясню отдельно ниже, там прячется ловушка.

```python
        l, n = X.shape
        X_train = np.hstack((X, np.ones((l, 1))))
```

`l, n = X.shape` — распаковка: число строк в `l`, число колонок в `n`.

`hstack` приклеивает справа столбец единиц — тот самый фиктивный признак из [главы 1](01_notaciya.md). Теперь `X_train` имеет `n+1` колонку.

```python
        self.w = np.linalg.inv(X_train.T @ X_train) @ X_train.T @ y
```

Вот она, формула, один в один:

```
np.linalg.inv(...)    →  (...)⁻¹        обратная матрица
X_train.T             →  Xᵀ             транспонирование
@                     →  умножение матриц

self.w = inv(XᵀX) @ Xᵀ @ y
```

```python
        return self
```

Возвращает сам объект. Это нужно, чтобы можно было писать цепочкой:

```python
regressor.fit(X, y).predict(X_test)
```

Так же устроен и sklearn.

## Метод predict

```python
    def predict(self, X):
        l, n = X.shape
        X_train = np.hstack((X, np.ones((l, 1))))
        y_pred = X_train @ self.w
        return y_pred
```

Та же подготовка (добавить столбец единиц) и одно умножение. Никаких вычислений весов — они уже найдены в `fit`.

Важно: **единицы нужно добавлять и здесь тоже**. Если забыть, размерности не сойдутся и умножение упадёт.

## Метод get_weights и зачем там copy

```python
    def get_weights(self):
        return self.w.copy()
```

В семинаре к этой строке есть комментарий, и он важный. Без `.copy()` метод вернул бы **ссылку** на тот же массив, что лежит внутри объекта. Тогда:

```python
w = regressor.get_weights()
w[0] = 999                      # хотели поменять свою копию
# а на самом деле испортили веса внутри модели
```

`.copy()` создаёт независимый массив — менять его безопасно.

Это общее правило Python: numpy-массивы и списки передаются по ссылке, а не копируются.

## Ловушка с размерностями

Вот зачем нужен `y[:, np.newaxis]`. Если его забыть:

```
y_pred имеет форму (8, 1)
y      имеет форму (8,)

y_pred − y   ->   (8, 8)    ← МАТРИЦА 8×8, а не столбец!
```

Numpy не ругается, а делает **бродкастинг**: растягивает оба массива и получает матрицу всех попарных разностей. Код продолжает работать, но считает полную чушь.

С `newaxis`:

```
y_pred (8, 1) − y[:, None] (8, 1)  ->  (8, 1)    ✓ правильно
```

Это одна из самых частых ошибок в numpy, и она **молчаливая**. Поэтому в семинаре и стоят `assert` — они ловят такое раньше, чем оно испортит результат.

## Что делает тестовый код

```python
regressor.fit(X_train[:, np.newaxis], y_train)
```

`X_train[:, np.newaxis]` — тот же приём: у нас один признак, и `X_train` одномерный `(25,)`. А `fit` требует двумерный. Превращаем в `(25, 1)`.

```python
def linear_expression(x):
    return 5 * x + 6

y = linear_expression(X) + np.random.randn(objects_num) * 5
```

Данные **генерируются искусственно**: берём известную прямую `y = 5x + 6` и добавляем случайный шум. Так мы знаем правильный ответ заранее и можем проверить, найдёт ли его модель.

`np.random.randn(50)` даёт 50 случайных чисел из нормального распределения, умножение на 5 увеличивает разброс.

Если после обучения веса получатся близкими к `5` и `6` — модель работает.
