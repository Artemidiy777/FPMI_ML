# 3. Градиентный спуск и класс MyGradientLinearRegression

## Зачем, если есть точная формула

Семинар отвечает одной фразой: «такое случается не для всех задач». Разверну:

- **Логистическая регрессия** — точной формулы не существует вообще, система не решается
- **Много признаков** — обращение матрицы `(XᵀX)⁻¹` стоит около `n³` операций; при 100 000 признаков это нереально
- **Данные не помещаются в память** — формула требует всю матрицу сразу

Поэтому в настоящем ML основной инструмент — спуск, а точная формула применяется редко.

## Формула градиента из семинара

```
∂L/∂w = (2/ℓ)(XᵀXw − Xᵀy) = (2/ℓ) Xᵀ(y_pred − y)
```

Два вида записи — одно и то же. Второй удобнее: `y_pred − y` это просто вектор ошибок, его легко посчитать.

## Откуда берётся

Раскрываем потерю:

```
L(w) = (1/ℓ)(wᵀXᵀXw − 2yᵀXw + yᵀy)
```

Дифференцируем по `w` слагаемое за слагаемым:

```
wᵀXᵀXw   →  2XᵀXw        аналог (ax²)' = 2ax
−2yᵀXw   →  −2Xᵀy        аналог (bx)' = b
yᵀy      →  0            константа, w в ней нет
```

Собираем и делим на `ℓ`:

```
∂L/∂w = (2/ℓ)(XᵀXw − Xᵀy)
```

Выносим `Xᵀ` за скобку:

```
= (2/ℓ) Xᵀ(Xw − y) = (2/ℓ) Xᵀ(y_pred − y)
```

## Это та же формула, что в ml_math

В [ml_math, глава 7](../../ml_math/07_obschiy_vyvod.md) мы вывели:

```
∂MSE/∂w = (2/n) Σ (ŷᵢ − yᵢ)·xᵢ
```

Матричная запись `Xᵀ(y_pred − y)` делает **ровно это**, только для всех признаков сразу. Умножение `Xᵀ` на вектор ошибок — это и есть «ошибка, умноженная на признак, просуммированная по объектам».

Разница только в форме записи: там цикл по точкам, здесь одно матричное умножение.

## Наследование классов

```python
class MyGradientLinearRegression(MyLinearRegression):
```

Скобки означают: **наследовать** от `MyLinearRegression`. Новый класс автоматически получает все методы родителя — `predict`, `get_weights` — и может переопределить то, что нужно.

Здесь переопределяется только `fit`. Метод `predict` используется родительский, потому что предсказание считается одинаково, независимо от того, как нашли веса.

```python
    def __init__(self, **kwargs):
        super().__init__(**kwargs)
```

`super()` — обращение к родителю. Строка означает «выполни конструктор родителя». `**kwargs` — «любые именованные аргументы, пробрось их дальше».

Польза наследования: не дублируем код. Если найдётся ошибка в `predict`, чинить придётся в одном месте.

## Разбор fit

```python
    def fit(self, X, y, lr=0.01, max_iter=100):
```

Два новых параметра:

- **`lr`** — learning rate, размер шага. То самое `α` из [ml_math, глава 6](../../ml_math/06_spusk.md)
- **`max_iter`** — сколько шагов сделать

```python
        self.w = np.random.randn(n + 1, 1)
```

**Стартовые веса — случайные**, а не нули. Форма `(n+1, 1)`: плюс один из-за фиктивного признака.

Для линейной регрессии это непринципиально — минимум один, придём в него откуда угодно. Для нейросетей случайная инициализация обязательна, там нули ломают обучение.

```python
        self.losses = []
```

Список для истории потерь — чтобы потом нарисовать график обучения.

```python
        for iter_num in range(max_iter):
            y_pred = self.predict(X)
            self.losses.append(mean_squared_error(y, y_pred))

            grad = self._calc_gradient(X_train, y, y_pred)

            assert grad.shape == self.w.shape, \
                f"gradient shape {grad.shape} is not equal weight shape {self.w.shape}"

            self.w -= lr * grad
```

Главный цикл, четыре действия на каждом шаге:

1. **Предсказать** текущими весами
2. **Записать** ошибку в историю
3. **Посчитать** градиент
4. **Сдвинуть** веса против градиента

Последняя строка `self.w -= lr * grad` — это и есть `w := w − α·∂L/∂w`.

**Про assert.** Он проверяет, что градиент имеет ту же форму, что веса. Если формы разошлись, `self.w -= lr * grad` не упадёт, а сделает бродкастинг и превратит веса в матрицу — та же молчаливая ловушка, что в [главе 2](02_analiticheskoe.md). Хорошая защита, стоит перенимать.

Проверил размерности:

```
X_train              (8, 2)
w                    (2, 1)
y_pred = X_train @ w (8, 1)
y_pred − y           (8, 1)
Xᵀ @ (y_pred − y)    (2, 1)    ← совпало с формой w
```

## Градиент отдельным методом

```python
    def _calc_gradient(self, X, y, y_pred):
        grad = (2. / X.shape[0]) * (X.T @ (y_pred - y))
        return grad
```

Формула в чистом виде: `(2/ℓ) · Xᵀ(y_pred − y)`.

`X.shape[0]` — число строк, то есть `ℓ`.

**Подчёркивание в начале имени** (`_calc_gradient`) — соглашение Python: «метод внутренний, снаружи его звать не надо». Технически ничего не запрещает, это просто пометка для читающего.

Вынесен в отдельный метод **не случайно**: следующий класс `MySGDLinearRegression` переопределит именно его, оставив весь остальной `fit` нетронутым. Это приём проектирования — выделить то, что будет меняться.

## Две ошибки, на которые легко нарваться

**Ошибка 1: передать не ту матрицу.** В цикле `predict(X)` получает `X` **без** столбца единиц (он сам его добавит), а `_calc_gradient(X_train, ...)` получает `X_train` **со** столбцом. Если перепутать — размерности разойдутся.

**Ошибка 2: не сохранить историю.** Без `self.losses` ты не увидишь, сходится обучение или разваливается. График потерь — первое, на что смотрят при отладке.
